### 📋 Known Deviations

#### 1. **Async Only**
- **Python**: Offers both sync (threading) and async (asyncio) APIs
- **Dart**: Only async/await (native to Dart)
- **Justification**: Dart's async model is built-in and doesn't require separate threading

#### 2. **Naming Conventions**
- **Python**: snake_case (get_current_values)
- **Dart**: camelCase (getCurrentValues)
- **Justification**: Dart style guide requires camelCase

#### 3. **Subscription API**
- **Python**: Async iterator (`async for entry in subscribe(...)`)
- **Dart**: Stream API (`.listen()`)
- **Justification**: Dart's Stream is the idiomatic async sequence type

#### 4. **No WebSocket Support**
- **Python**: Supports both gRPC and WebSocket
- **Dart**: Currently gRPC only
- **Justification**: gRPC is primary protocol; WebSocket can be added if needed

#### 5. **No CLI**
- **Python**: Includes command-line interface
- **Dart**: Library only
- **Justification**: Focus on library for Flutter apps

## Performance Comparison

### Complexity Analysis

| Operation | Python | Dart | Big-O |
|-----------|--------|------|-------|
| Connect | O(1) | O(1) | Same |
| Get values (n paths) | O(n) | O(n) | Same |
| Set values (n paths) | O(n) | O(n) | Same |
| Subscribe | O(1) | O(1) | Same |
| Path→ID lookup | O(1) | O(1) | Same (HashMap) |

### Practical Considerations

1. **Startup Time**
   - Dart: Faster (compiled vs interpreted)
   - Expected: ~50% faster cold start

2. **Memory Usage**
   - Dart: Lower overhead (no interpreter)
   - Expected: ~30% less memory

3. **Network Performance**
   - Similar (both use gRPC C core)
   - Latency: Comparable

4. **Concurrency**
   - Python: asyncio event loop
   - Dart: Native async/await + isolates
   - Dart has better multi-core utilization
